# 演示脚本（设备 → 转写 → 病历）

一次完整的现场演示约 5 分钟。按下面的顺序做，别临场改流程。

## 0. 演示前 30 分钟检查

| 检查 | 命令 / 动作 | 通过标准 |
| --- | --- | --- |
| 板子在线 | 设备管理器看 `COM5` | 有 CH343 的 COM 口 |
| 固件是最新的 | 打开串口助手（921600） | 能看到 `seg_tx: 环形缓冲 60 秒…模式=连续流` |
| 后端能起 | 见第 2 节 | `/api/health` 返回 `status: ok` |
| 前端能开 | 见第 2 节 | 页面左侧有会话列表 |
| 云端 Key 有效 | 界面里点一次「重新生成」 | 能返回字段，不报 401 |
| 麦克风电平 | 串口日志 | 噪声底 -80 ~ -65 dB（不是 -100） |

> 提前录一场作为**兜底**：万一现场网络或硬件出问题，直接打开已有会话继续讲界面。

## 1. 接线

见 [hardware.md](hardware.md)。要点：VDD→3V3、GND→GND、L/R→GND、SCK→IO5、WS→IO4、SD→IO6。

## 2. 启动（两个窗口，提前开好）

**窗口 1：后端**

```powershell
Set-Location -LiteralPath 'D:\esp32\source code\zhenlu-assistant-public-main\backend'
Remove-Item Env:ZHENLU_DEVICE_STATE_FILE -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

**窗口 2：前端**

```powershell
Set-Location -LiteralPath 'D:\esp32\source code\zhenlu-assistant-public-main\frontend'
npm run dev
```

浏览器打开 **http://localhost:5173/**，保持这个标签页。

> 不要设 `ZHENLU_DEVICE_STATE_FILE`——那是受管模式，没有设备心跳时写操作会被拒（界面顶部会出现"设备已断开"的黄条）。

## 3. 演示流程

### ① 开场（30 秒）

> "这是诊录助手：一个面向小门诊的语音病历终端。医生说话，它把问诊变成结构化病历草稿，医生核对确认后直接粘贴进 HIS。"

指着板子："采集端是 ESP32-S3 加一个数字麦克风，端侧做语音分段，只把说话的部分传上去。"

### ② 开始录音（30 秒）

```powershell
Set-Location -LiteralPath 'D:\esp32\source code\zhenlu-assistant-public-main'
D:\anaconda\python.exe desktop\recorder.py --port COM5
```

看到 `已开始接收音频` 后说一句：

> "现在它在录了。注意它是**连续采音**，不是一句一个请求——整场对话最后一次性送识别，模型能看到完整上下文。"

### ③ 演一遍问诊（2 分钟）

照着念（每句停 1~2 秒，最后一句说完等 18 秒）：

> ① 我咳嗽、咳痰五天了，这两天还有点发烧。
> ② 晚上咳得更厉害，痰是白色的，没有胸闷气短。
> ③ 我有高血压三年了，一直吃降压药控制着。
> ④ 自己吃过连花清瘟，没什么效果。
> ⑤ 对了，我青霉素过敏。

终端出现 `会话结束：xx s` 和 `已上传会话` 后，转到浏览器刷新。

### ④ 界面演示（2 分钟）

按这个顺序点，**每点一下说一句**：

1. 打开会话 → "转写在这里，每句都有时间戳"
2. 点「生成病历草稿」→ "五个字段自动填好，没提到的写'未提及'，不编造"
3. 点某个字段的「查看来源」→ 右侧出现原句，"每条结论都能追到原话"
4. 点「定位播放」→ "点一下就能回听当时那句话"
5. 改一个字 → 「保存修改」→ "医生改过的内容，重新生成时不会被覆盖"
6. 「确认病历」→ "确认后锁定成只读版本，复制进 HIS"

### ⑤ 可选：设备门禁（30 秒，想强调"专用硬件"时加）

后端带 `ZHENLU_DEVICE_STATE_FILE` 启动、录音代理带 `--state-file` 运行时：

1. 代理运行中 → 界面正常，可写
2. 按 Ctrl+C 停掉代理 → **8 秒后界面顶部弹出"设备已断开，新的操作已暂停"**，此时点"保存修改"会被拒绝（423）
3. 重新运行代理 → 黄条消失，恢复可写

一句话总结："没有设备就不能写病历——这是硬件终端的价值，不只是个麦克风。"

### ⑥ 收尾（30 秒）

> "端侧只做了两件事：切段和时间轴对齐。省的是流量和识别费用——实测上传时长约为原始录音的 78%。"

## 4. 可能被问到的问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么不用普通麦克风？ | 按键和状态反馈让录音脱离电脑窗口；端侧缓存和重传保证弱网不丢 |
| 识别准不准？ | 目前是功能验证：单句文本正确、字段能抽对；**还没有评测集，不给准确率数字** |
| 延迟多少？ | 说完到出草稿：静音等待 18 s + 转写约 1 倍时长 + 千问约 5 s。可调短 |
| 断网怎么办？ | 当前版本会丢；设计里是分片缓存+补传，属于下一阶段 |
| 数据安全？ | 录音与文本存本机 SQLite 和本地目录，云端只走识别/生成接口；Key 在本机 `.env`，已 gitignore |
| 和竞品差别？ | 单诊室起步、字段可回溯到原话、模板化复制，不碰 HIS 数据库 |

## 5. 卡住了怎么办

| 症状 | 处理 |
| --- | --- |
| 串口打不开 | 关掉串口助手 / VS Code 监视器，它们占着 COM5 |
| 终端没有"会话开始" | 看有没有 `已接收 xx s 音频` 心跳；有就说明串口通、麦克风没拾音，检查接线 |
| 上传报 401/403 | Key 失效或没开通服务，换 Key 重启后端 |
| 转写很慢 | 正常，约等于录音时长；先讲界面，等它回来 |
| 后端起不来 `10048` | 8000 端口被占，先关掉上一个后端 |
| 页面顶部黄条 | 环境变量 `ZHENLU_DEVICE_STATE_FILE` 还在，按第 2 节删掉重启 |

**兜底**：直接打开之前录好的会话，讲界面部分。演示的核心价值在"结构化 + 可追溯 + 确认复制"，录音只是入口。
